# График отпусков — многопользовательская серверная версия

## Быстрый запуск на Windows + Docker Desktop

1. Установите и запустите Docker Desktop.
2. Распакуйте архив, например в `C:\VacationDashboard`.
3. Откройте PowerShell:

```powershell
cd C:\VacationDashboard
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\deploy.ps1
```

Первый запуск создаст `.env` и откроет его в Блокноте. Укажите пользователей:

```env
VACATION_USERS=admin:СложныйПароль,zaved_gp56:ПарольГП56,zaved_dpo48:ПарольДПО48
```

Не используйте в паролях запятые и двоеточия. Сохраните `.env` и повторно запустите `deploy.ps1`.

После запуска откройте `http://localhost:8086`.

## Доступ коллег из локальной сети

Коллеги используют адрес `http://IP-АДРЕС-КОМПЬЮТЕРА:8086`.

Откройте PowerShell от имени администратора и разрешите порт:

```powershell
New-NetFirewallRule -DisplayName "Vacation Dashboard 8086" -Direction Inbound -Protocol TCP -LocalPort 8086 -Action Allow
```

Не публикуйте порт в интернет. В базе хранятся ФИО; для внешнего доступа требуются HTTPS и обратный прокси.

## Хранение и синхронизация

- Единая база: `data\vacation.db`.
- SQLite использует WAL: параллельные чтения и короткие безопасные записи.
- У сотрудника есть версия записи. Если два пользователя одновременно меняют одного сотрудника, сохранится первая правка; второй пользователь получит конфликт и данные обновятся.
- Изменения разных сотрудников сохраняются параллельно.
- Браузер опрашивает версию сервера раз в 15 секунд и подгружает правки коллег.
- Автоматических суточных копий в этой компактной сборке нет: используйте `backup.ps1` и копируйте папку `data` на защищённый носитель.

## Проверка и применение правок внешнего разработчика

Папку может редактировать внешний разработчик, а в ней же лежит рабочая база
(`data\vacation.db`). Чтобы не потерять контроль над тем, что попадает в боевой
контейнер, используйте `apply-changes.ps1`.

Скрипт ведёт «эталон» — снимок исходников в том виде, в каком они были успешно
применены (собраны) в прошлый раз. Эталон хранится в `.codewhale\baseline` и в
образ не попадает (каталог `.codewhale` есть в `.dockerignore`).

```powershell
.\apply-changes.ps1            # проверить, показать diff, спросить, применить
.\apply-changes.ps1 -Check     # только проверить и показать изменения
.\apply-changes.ps1 -Yes       # применить без вопроса (автоматизация)
.\apply-changes.ps1 -Reinit    # пересоздать эталон из текущего состояния
```

Что делает скрипт при запуске:

1. сравнивает все отслеживаемые файлы с эталоном (изменённые, добавленные, удалённые);
2. показывает построчный diff по каждому файлу;
3. запрашивает подтверждение;
4. после подтверждения: останавливает контейнер, делает согласованную копию БД
   в `data\backups\pre-apply-<дата>.db`, выполняет `docker compose up -d --build`,
   проверяет `/healthz` и обновляет эталон.

Не отслеживаются: `data\` (рабочая БД и бэкапы), `.codewhale\`, временные и
двоичные файлы. Изменения `.env` учитываются и применяются при пересборке.

**Первый запуск.** Если эталона ещё нет, скрипт создаёт его из текущего
состояния папки. Если в папке лежат ещё не применённые правки, сначала выполните
`.\deploy.ps1` — иначе эти правки будут считаться уже применёнными.

## Управление

```powershell
.\stop.ps1              # остановить контейнер, данные сохраняются
.\deploy.ps1            # запустить/обновить
.\backup.ps1            # копия базы в data\backups

docker compose logs -f   # посмотреть логи
```

## Важно

Все авторизованные пользователи пока имеют одинаковые права. Роли «заведующий видит только своё подразделение» — отдельная следующая задача.
